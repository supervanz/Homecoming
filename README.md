# Homecoming: Reentry

AI에게 지구를 빼앗기고 우주로 쫓겨난 인간 유랑객이, 개조된 옛 인공위성 병기를 뚫고 지구 대기권으로 재진입하는 **3D 탑다운 종스크롤 슈팅**입니다.

| 스테이지 | 보스 발악 | 대기권 돌입 | 엔딩 |
|---|---|---|---|
| ![스테이지 시작](docs/images/v_start.jpg) | ![보스 발악 패턴](docs/images/v_critical.jpg) | ![대기권 돌입](docs/images/v_end_heat.jpg) | ![WELCOME HOME](docs/images/v_end_welcome.jpg) |

세로 9:16 화면 기준입니다.

---

## 1. 프로젝트의 목적

이 프로젝트는 **수업 라이브 데모**용입니다. 목표는 두 가지입니다.

1. **5분 안에 끝나는, 처음부터 끝까지 돌아가는 완성된 게임**을 만든다. (타이틀 → 웨이브 → 보스 2페이즈 → 대기권 재진입 엔딩 → 결과)
2. 그 과정을 **AI 코딩 에이전트(Claude Code)와 Unity CLI로 진행하는 방법**을 학생들에게 보여 준다. 사람은 기획하고, 결정하고, 승인하고, 직접 플레이해 확인한다. AI는 계획을 보여 주고, 만들고, 스스로 검증하고, 결과를 그대로 보고한다.

결과물보다 **과정**이 중요한 프로젝트입니다. 기획서와 작업 규칙은 [`CLAUDE.md`](CLAUDE.md)에 있으니 이 README와 함께 읽어 보세요.

## 2. 게임 소개

- **이야기**: 인간 유랑선이 AI가 장악한 궤도 방어망(옛 인공위성을 개조한 병기)을 뚫고 귀향한다. 보스(폐 우주정거장)를 쓰러뜨리면 대기권에 재진입하고 "WELCOME HOME"으로 끝난다.
- **색이 곧 서사**: 인간(플레이어)은 따뜻한 주황, AI(적)는 차가운 흰 금속과 붉은 센서·탄. 엔딩에서 검은 우주(추방)가 파란 하늘(귀향)로 바뀐다.
- **5분 스테이지**

| 시간 | 구성 |
|---|---|
| 0:00 ~ 0:30 | 잡몹 위성 편대 (조작 익히기) |
| 0:30 ~ 1:30 | 조준 위성, 궤도 포대, 첫 파워업 |
| 1:30 ~ 2:30 | 중형 캐리어, 밀도 상승 |
| 2:30 ~ 3:00 | 휴식, 지구 등장, WARNING |
| 3:00 ~ 4:30 | 보스전: 외피(부위 파괴) → 코어 노출 → 발악 |
| 4:30 ~ | 대기권 재진입 엔딩 (27초) |

- **시스템**: 체력제와 피격 후 무적, 무기 3단계 강화, 폭탄(적 탄 제거 + 광역 피해), 보스 부위 파괴, 손상 상태 이펙트, 화면 흔들림과 히트스톱, 덕킹이 있는 사운드 믹싱.

## 3. 실행 방법

### 필요한 것

- **Unity 6000.6.6f1** (`ProjectSettings/ProjectVersion.txt`)
- **Git LFS**: 모델(.glb), 음원(.mp3/.wav), 이미지는 LFS로 관리합니다. clone 전에 `git lfs install`을 한 번 실행하세요.

```bash
git lfs install
git clone https://github.com/supervanz/Homecoming.git
```

### 플레이

1. Unity Hub에서 프로젝트를 연다.
2. Game 창 해상도를 **9:16 세로** (예: 1080×1920)로 맞춘다. 다른 비율에서도 화면 안에 들어오도록 카메라가 자동으로 물러나지만, 9:16 기준으로 배치되어 있다.
3. `Assets/_Project/Scenes/Title.unity`를 열고 Play.

| 동작 | 키보드 | 게임패드 |
|---|---|---|
| 이동 | WASD / 방향키 | 왼쪽 스틱 |
| 사격 (누르고 있는 동안 연사) | Space | South 버튼 |
| 폭탄 | B | East 버튼 |
| 결과 화면: 재시작 / 타이틀 | Space / Esc | |
| 디버그 표시 / 화면 흔들림 켜고 끄기 | F1 / F2 | |
| 엔딩만 바로 재생 (개발 빌드) | F3 | |

## 4. 만든 과정

### 4-1. 순서: 못생겨도 끝까지 돌아가는 게임이 먼저

| 막 | 마일스톤 | 내용 |
|---|---|---|
| 기초 | M1 | Unity CLI로 프로젝트 생성 (URP, Input System, WebGL 타깃, GitHub) |
| 프리미티브로 완성 | M2 ~ M6 | 플레이어 → 적 3종과 웨이브 → 파워업·폭탄 → 보스 2페이즈 → HUD와 게임 흐름. **M6에서 회색 도형으로 처음부터 끝까지 플레이 가능** |
| 완성도 올리기 | M7 ~ M9 | 생성 3D 모델 교체, 효과음·음악·VFX, 카메라·라이팅·포스트프로세싱·엔딩 |
| 다듬기 | M10 | 봇 시뮬레이션과 밸런스 대시보드 (실제로는 M7~M9보다 먼저 진행) |
| 내보내기 | M11 | WebGL 빌드 → Unity Play 업로드 (**아직 안 함**) |

외형(모델)과 로직(컴포넌트)을 처음부터 분리해 두어서, 회색 도형을 생성 모델로 바꿔도 로직은 그대로 동작합니다.

### 4-2. 사람과 AI가 나눈 일

마일스톤마다 같은 흐름을 반복했습니다. 아래 지시는 이 프로젝트에서 실제로 쓴 것입니다.

1. **기획서와 작업 규칙을 먼저 쓴다.** `CLAUDE.md` 0장에 AI 작업 원칙을 적었다: 실패하면 우회하지 말고 멈춰서 보고, 삭제·패키지·비용이 드는 일은 사전 승인, 실제로 확인한 것만 "완료", 한 번에 한 마일스톤.
2. **만들기 전에 읽고 질문하게 한다.** 첫 지시:
   ```
   CLAUDE.md를 처음부터 끝까지 읽어.
   1) 이 게임을 세 문장으로 요약하고
   2) 0장 AI 작업 원칙 중 가장 중요한 세 가지를 말하고
   3) 기획에서 모호하거나 충돌하는 부분이 있으면 질문해.
   아직 아무것도 만들지 마.
   ```
   AI가 던진 질문에 사람이 답해 결정했다: "체력제로 결정", "스페이스 누르는 동안 자동사격", 충돌은 물리 엔진 대신 평면 거리 계산.
3. **마일스톤마다 계획을 보고 승인한다.** "Plan M2" → AI가 무엇을, 어느 파일에, 어떻게 확인할지 보여 줌 → "제안한대로 작업진행".
4. **만들고, AI가 먼저 검증한다.** AI는 컴파일 오류와 콘솔을 확인하고, 플레이 모드에서 상태를 읽고 화면을 캡처해 스스로 본다. 사람은 직접 플레이해 손맛을 본다 → "Works, commit M2".
5. **마일스톤 단위로 커밋한다.** `[M2] Player movement, firing and roll` 형식. 그 마일스톤의 파일만 커밋한다.
6. **비용과 되돌리기 어려운 일은 매번 묻는다.** 패키지 설치, 생성 포인트(견적과 최악의 경우), 삭제는 실행 전에 승인. 비싼 3D 생성 전에는 원화를 먼저 확인한다.
7. **밸런스는 데이터로.** "M10 밸런스 조정 시스템부터 진행해줘. 먼저 봇 플레이 테스트 하고 내가 난이도 조정에 필요한 파라메터들을 조정할 수있게"
8. **문제가 생기면 원인과 선택지를 받고 사람이 고른다.** "플레이어 기체와 적기들이 화면 바깥까지 나가는 문제가 있다" → 원인(화면이 세로로 바뀜)과 선택지 3개 → "세로화면 기준으로 고쳐줘".

### 4-3. 에셋 만들기 (Unity AI Generators)

3D 모델은 아래 순서로 만들었습니다. 원화가 싼 반복 지점이고, 3D 복원은 비싸서 원화를 확인한 뒤 한 번만 돌립니다.

```
컨셉 원화 (Nano Banana 2.1) → 배경 제거 (Photoroom) → 3D 복원 (Tripo P2, glb 10k faces)
→ glTFast 임포트 → ModelSwapBuilder로 프리미티브와 교체 (재질, 방향, 크기, 높이)
```

| 종류 | 개수 | 모델 |
|---|---|---|
| 3D 모델 | 5 (플레이어, 잡몹 위성, 조준 위성, 캐리어, 보스 외피) | Tripo P2 |
| 음악 | 6 | ElevenLabs Music |
| 효과음 | 28 | ElevenLabs Sound Effects |
| 지구 텍스처, 파티클 텍스처 | — | 코드로 절차적 생성 |

도구, 단계, 사용 포인트(합계 2,004)는 [`Assets/_Project/CREDITS.md`](Assets/_Project/CREDITS.md)에 기록되어 있습니다.

### 4-4. 밸런스: 봇 시뮬레이션

- 사람과 **같은 입력 인터페이스**로 조종하는 봇 (치트 없음). 실력 3단계(초보·보통·숙련)는 반응 지연, 회피 정확도, 폭탄 판단으로 구분.
- 판마다 시드를 고정해 같은 판을 재현할 수 있다. 결과는 `BalanceReports/`에 CSV와 요약으로 저장.
- 실행은 메뉴 **Homecoming → Run Bot Simulation**, 난이도 값은 **Homecoming → Balance Dashboard** 창에서 조정.

## 5. 프로젝트 구조

```
Assets/_Project/
  Scripts/   Core, Player, Weapon, Enemy, Boss, Bot, Audio, VFX, Ending, UI
  Data/      밸런스·웨이브·보스 패턴·VFX·사운드 설정 (ScriptableObject)
  Editor/    에셋과 씬 연결을 다시 만드는 빌더, 시뮬레이션 실행기, 대시보드
  Prefabs/ Scenes/ Art/ Audio/ VFX/ UI/
CLAUDE.md    기획서 + AI 작업 원칙
```

- 밸런스 수치(체력, 속도, 연사 간격, 드롭 확률, 웨이브 구성)는 모두 ScriptableObject라 코드 수정 없이 조정할 수 있습니다.
- 탄과 적, 이펙트는 오브젝트 풀링을 씁니다 (WebGL 성능 고려).
- 보이는 것은 3D, 이동과 충돌은 하나의 평면(XZ) 위 원형 거리 계산입니다. 카메라 각도와 상관없이 보이는 위치와 판정이 일치합니다.
- 메뉴 **Homecoming**의 빌더(`Build VFX`, `Build Ending (M9)`, `Swap Generated Models (M7)`, `Apply Portrait Layout (9:16)` 등)는 배율을 곱하지 않고 목표값을 직접 쓰므로, 여러 번 실행해도 같은 결과가 나옵니다.

## 6. 한계와 알려진 문제

정직하게 적습니다. 수업에서 "AI와 만들면 무엇이 남는가"를 이야기할 때 같이 보세요.

**아직 하지 않은 것**
- **M11 WebGL 빌드와 Unity Play 업로드를 하지 않았습니다.** 지금은 에디터에서만 플레이할 수 있습니다. 세로 캔버스 설정과, WebGL이 쓰는 Mobile 품질 단계에서 포스트프로세싱이 제대로 나오는지 확인이 필요합니다.
- **세로 배치 후 밸런스를 다시 맞추지 않았습니다.** Normal 난이도, 보통 봇 3판에서 클리어 0판(목표 40~60%)이고 모두 보스 1페이즈에서 죽었습니다. 화면 폭이 16 → 10으로 좁아져 회전 링 탄을 피할 공간이 줄었을 가능성이 큽니다. 다만 Normal 프리셋 자체가 원래 플레이어에게 불리하게 잡혀 있어(폭탄 0개, 피격 판정 1.57배) 원인을 하나로 단정할 수 없습니다.

**품질상 한계**
- 보스 코어와 좌우 태양전지판 포대는 아직 회색 도형(프리미티브)입니다. 생성 비용을 고려해 보스는 외피만 생성 모델로 바꿨습니다.
- 조준 위성과 캐리어의 붉은 센서는 텍스처일 뿐 빛나지 않습니다.
- 생성 3D 모델은 한 장의 원화에서 복원한 것이라 뒷면과 세부 형태는 모델이 추측한 결과입니다.
- 엔딩의 "WELCOME HOME" 등장 순간과 엔딩 곡의 멜로디 정점이 맞는지 확인하지 않았습니다 (생성 음악이라 곡 구조를 정할 수 없었음).
- 타이틀 화면에는 UI가 두 번 그려지는 문제가 남아 있습니다(글자가 고정이라 눈에 띄지 않음). 스테이지 화면에서는 고쳤습니다.
- 각 곡에 같은 "귀향 테마" 멜로디가 들어 있다는 보장은 없습니다. 생성 음악은 분위기만 맞췄습니다.

**환경 의존성**
- Unity 6000.6.6f1과 실험판·프리뷰 패키지(`com.unity.pipeline 0.10.0-exp.1`, `com.unity.ai.assistant 2.21.0-pre.2`)를 씁니다. 다른 에디터 버전이나 계정에서는 패키지를 받지 못해 프로젝트를 열 때 오류가 날 수 있습니다. `com.unity.pipeline`은 AI 에이전트가 에디터를 조종할 때 쓰는 패키지라 게임 실행에는 필요하지 않습니다.
- 모델과 음원은 Git LFS에 있어서, LFS 없이 clone 하면 파일 대신 포인터만 받아집니다.

**AI와 작업하며 겪은 문제 (일부)**
- 패키지를 하나 설치하자 URP가 머티리얼을 재검사하면서 피탄 플래시에 필요한 설정이 조용히 꺼졌다. 에러가 나지 않아 눈으로 확인하기 전까지 몰랐다.
- `Mathf.SmoothStep`을 셰이더의 `smoothstep`처럼 썼다가 지구 텍스처가 하얗게 나왔다. 이름이 같아도 동작이 다르다.
- 새 모델이 프리미티브보다 높아서 밑을 지나는 적 탄을 가렸다. "적 탄이 항상 가장 잘 보여야 한다"는 기획 규칙(13-1)을 화면을 보고서야 발견했다.
- 화면 비율이 바뀌자 게임 영역이 화면 밖으로 넘쳤다. 코드는 그대로인데 결과가 달라진 경우라, 사람이 플레이하며 보고해야 알 수 있었다.
